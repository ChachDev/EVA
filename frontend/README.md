# EVA · Frontend

Новый интерфейс основан на предоставленном `EVA_Design_Kit.zip`: React, TypeScript, Vite, локальные шрифты Open Sans и SVG-иконки Lucide. Исходное описание набора сохранено в [design/EVA_DESIGN_KIT_SOURCE.md](design/EVA_DESIGN_KIT_SOURCE.md).

## Локальный запуск

Нужен Node.js 22.12+. Из `frontend/`:

```powershell
npm ci
npm run dev
```

Приложение открывается на http://127.0.0.1:5173/. По умолчанию работает серверный интерфейс `LiveApp`: Backend ожидается на `http://127.0.0.1:8000`. Vite слушает только loopback, порт фиксирован. `VITE_API_URL` позволяет явно указать другой backend. При недоступности API показывается ошибка, автоматического перехода на демо нет. Переменные Vite задаются перед запуском или сборкой.

Прежний дизайн-прототип доступен только при явном `VITE_API_MODE=demo`. В серверном режиме его `localStorage` и вымышленные оценки не читаются. `VITE_*` публичны: секреты туда не помещать.

```powershell
npm run build
npm run preview
```

Сборка включает строгую проверку TypeScript. Предпросмотр сборки — http://127.0.0.1:4173/.

## Экраны и действия

- `#/overview` — реальные количества диалогов, оценок и открытых апелляций. Демо-графики и неподтверждённые KPI сюда не переносятся.
- `#/dialogs` — серверный список, поиск по ID и фильтры по языку/каналу.
- `#/dialogs/<id>?evaluation=<id>` — выбор версии чек-листа, запуск оценки, история, неизменяемый снимок входов, текущий пересмотренный итог, доказательства и JSON-экспорт.
- `#/checklists` — редактирование всех полей критериев, допустимых ступеней и условий N/A; публикация новой версии с `base_version`. Прежние версии сохраняются.
- `#/appeals` — создание обращения из критерия, принятие/отклонение с причиной и доказательствами, серверный пересчёт. Для изменения используется точная ревизия.
- `#/audio/<job-id>` — состояние сохраняемого задания, локальный плеер, подтверждение ролей и переход к созданному транскрипту. Адрес позволяет вернуться после reload; также можно вставить ID задания.
- Дизайн-система `#/brand` и прежние демонстрационные сценарии доступны в явном деморежиме.

Новый диалог принимает ручной ввод, JSON или TXT; JSON-запрос целиком ограничен 1 МиБ, до 10 000 реплик. JSON поддерживает массив, `messages`, `transcript` или envelope с **одной** записью `records`/`data.records`. Поля: `text`, `role`/`speaker`, `time`/`timestamp`. TXT: `[00:00] клиент: текст`, с явными временем и ролью на каждой строке. Неизвестные роли и отсутствующее время отклоняются. Для чатов требуется MM:SS, для готовых транскриптов звонков — ISO с часовым поясом. Язык и канал пользователь выбирает в форме.

Сохранение вызывает `POST /api/v1/conversations`; оценка запускается отдельно. Транскрипты передаются только настроенному Backend, в localStorage не сохраняются. Баллы, нормированные вклады, флаги и evidence берутся только с сервера. Неопределённость не превращается в N/A. История загружается со всех страниц, review-case показывает текущую ревизию; после идемпотентного ответа действия запрашивается актуальный review-case.

Загрузка аудио отправляет raw WAV/MP3/FLAC/Ogg до 25 МиБ, затем отдельно запрашивает ASR. При отсутствии ASR файл остаётся сохранённым, пользователь видит его ID и ошибку. Внешняя ссылка записи открывается только явным нажатием; автоматического скачивания нет.

Только демонстрационный `App.tsx` использует `eva-freedom-demo-v1` в localStorage. Реальный интерфейс не подменяет сбой API данными этой демонстрации.

## Границы этой версии

Backend подключён. Доступность настоящего ML/ASR проверяется отдельно: работа UI и синтетических тестов не подтверждает качество модели. В текущем окружении ML не запущен, ASR не настроен; соответствующие действия возвращают явные ошибки без вымышленных результатов.

Каждую оценку должен утвердить человек. Отдельного API утверждения пока нет, поэтому UI помечает все оценки как предварительные. Решение по апелляции не выдаётся за утверждение. Прямой ручной review, долговечные задания оценки, исправление ASR-текста, аутентификация и список аудиозаданий остаются отдельными задачами Backend/ML. Историческая запись без snapshot доступна для чтения, пересмотр заблокирован. После timeout сначала проверяйте историю: автоматического повторного inference нет.

Для большого объёма истории понадобится агрегирующий API: сейчас UI читает все страницы оценок и review-case для каждой с ограничением в четыре параллельных чтения. Исходные DTO и успешные v1-контракты не менялись.

## Структура

- `src/LiveApp.tsx`, `LiveForms.tsx`, `LiveDetail.tsx` — серверные маршруты, формы, история и разбор.
- `src/api/` — канонические типы и HTTP-клиент; `server-input.ts` — строгий разбор ввода без угадывания ролей/времени.
- `src/App.tsx` — прежние демонстрационные разделы и локальные сценарии.
- `src/eva-data.ts` — вымышленные примеры и расчёт демонстрационных баллов.
- `src/eva-detail.tsx`, `src/eva-ui.tsx` — разбор и общие элементы.
- `src/eva-storage.ts` — проверка данных браузерного хранилища.
- `src/globals.css` — стили набора, ограниченные `#eva-root`; reduced motion сохранён.
- `public/brand`, `public/fonts`, `public/downloads` — локальные ресурсы набора.

## Проверки интеграции

`npm run build` проверяет TypeScript и собирает Vite. `node --test tests/client.test.mjs tests/server-input.test.mjs` использует Node 22.18+ со встроенным выполнением TypeScript; проверяет клиент, форматы, лимиты, ошибки и идемпотентные запросы без настоящего сервиса.

Для browser workflow запустите **отдельный** `backend/tests/browser_server.py --port 58123` окружением Backend и обычный frontend. Укажите `EVA_BROWSER_TEST_BACKEND=http://127.0.0.1:58123`, при необходимости `EVA_PLAYWRIGHT_PATH` до установленного локально Playwright и запустите `node tests/browser-integration.mjs`. Требуется установленный Edge (или `EVA_BROWSER_CHANNEL`). Тест перенаправляет API только внутри своего браузерного контекста на синтетический backend, не меняет настройки основного UI или основную БД. Каждый прогон требует свежего тестового сервера. Снимки сохраняются в игнорируемый `frontend/artifacts/integration/`. Это проверка API и интерфейса, не настоящий ML.

Работа ведётся в `main`, без автоматического commit, push или публикации.
