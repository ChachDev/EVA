# Визуальные направления EVA

Три альтернативы первого макета, подготовленные 7 ноября 2026 по запросу пользователя. Это интерактивные дизайн-иллюстрации для выбора направления, а не реализация API или новая версия работающего приложения.

Метод: [unslop](https://github.com/heydamir/unslop) by Damir Sokolovsky, [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/). Навык прочитан и применён без глобальной установки. Права, запреты на Git/публикацию и границы frontend сохранены.

## Аудит первого варианта

- Рабочие подписи и критерии слишком мелкие: местами 9–11 px.
- Зелёный цвет одновременно выделяет меню, оценку, аудио, иконки и действия.
- Расшифровка и оценка имеют почти равный визуальный вес, хотя доказательство важнее общего балла.
- Интервалы 7, 9, 17, 19 px не образуют единого ритма.
- Общие лозунги и декоративное обозначение ИИ создают шум на рабочем экране.

## Направления

### Рабочая консоль

- Продукт: последовательная проверка разговоров специалистом качества.
- Характер: собранный, точный, спокойный.
- Среда: рабочий стол аудитора с очередью дел.
- Главный момент: выделенная реплика рядом с объяснением критерия.
- Подпись: одна тонкая зелёная отметка связывает выбранное дело и доказательство.

Слева очередь, в центре разговор, справа инспектор критерия. Общая оценка показана числом без большого кольца. Нейтральная навигация освобождает внимание для содержания.

### Протокол

- Продукт: вдумчивая проверка и обсуждение оснований оценки.
- Характер: обстоятельный, читаемый, сдержанный.
- Среда: документ с замечаниями на полях.
- Главный момент: связь реплики и аннотации на полях.
- Подпись: таймкод как ссылка на доказательство.

Горизонтальная навигация, документ вместо набора карточек, просторная расшифровка и компактный плеер внизу. Выразительность создаётся типографикой и расположением текста.

### Аудиостудия

- Продукт: разбор спорных эпизодов голосового разговора.
- Характер: инструментальный, внимательный, последовательный.
- Среда: аудиоредактор и дорожки разговора.
- Главный момент: крупная временная шкала с двумя дорожками и маркерами замечаний.
- Подпись: курсор времени связывает звук, реплику и основание оценки.

Доминирует аудиопанель, ниже — текст и критерии. Остальная оболочка нейтральная. Записи нет: дорожки синтетические, управление иллюстрирует переходы без воспроизведения аудио.

## Что изменено по проходам unslop

1. Интервалы приведены к шагу 4 px; группы и колонки выровнены.
2. Цветовые поверхности приглушены; акцент связан с выделением и доказательствами.
3. Иконки сведены к необходимым действиям; декоративные sparkles удалены.
4. Текст описывает звонок и причину решения, без общих приветствий и лозунгов.
5. Используется локально встроенный IBM Plex Sans из зависимостей проекта, два основных веса и 600 для редких акцентов. Основной текст реплик 14–15 px.
6. Созданы три разные организации одного рабочего сценария.
7. У критериев есть явное обоснование, цитата и переход по времени.
8. Визуальный материал взят из предмета продукта: реплики и синтетическая временная шкала. Генерация изображений не использовалась.
9. Нет автозапуска аудио, декоративных циклических анимаций и фоновых API-запросов.

## Файлы и воспроизведение

- `eva-visual-directions.html` — единый HTML-фрагмент для встроенного просмотра и карусели вариантов.
- `parts/console.html`, `parts/protocol.html`, `parts/studio.html` — редактируемые варианты.
- `parts/interactions.js` — локальная логика таймкодов, критериев, проверки и апелляции.
- `build_preview.py` — сборка фрагмента из частей с встраиванием шрифтов из frontend/node_modules.
- `FONT-LICENSE.txt` — лицензия встроенного IBM Plex Sans.
- `.gitignore` — исключает локальную папку проверки `work/`.
- `work/` — игнорируемые локальные материалы проверки.

Из frontend: `python design/build_preview.py`. Для просмотра используется стандартная оболочка visualize; runtime карусели и Tweak предоставляет хост. В обычном браузере сам фрагмент требует такой оболочки.

## Проверки

- `npm run build` — успешно: TypeScript и Vite, исходное приложение не изменялось.
- Браузер Edge: переключение трёх вариантов, критерии и связанные реплики, таймкоды, подтверждение оценки, обязательная причина апелляции и локальное сохранение — успешно.
- Проверены светлая и тёмная темы, ширины области 1024, 736, 358 и 320 px. Ошибок JavaScript и горизонтального переполнения не найдено после исправления сжатия аудиодорожек.
- Установка объявленных зависимостей сначала завершилась ошибкой доступа к registry; повторная установка через автоматическое разрешение среды прошла успешно. Временный npm-кэш удалён.
- Backend/ML и HTTP-режим не запускались: эти макеты не используют API. Git и GitHub не изменялись.

## Данные и ограничения

Все данные синтетические; четыре критерия и 85,5/100 сохранены из первого дизайн-примера для честного сравнения вариантов. Это НЕ канонический fixture из contracts и НЕ ответ ML. Никакой расчёт серверных оценок не реализуется; в макете показаны заранее заданные числа.

Реализация выбранного направления должна использовать динамические критерии из contracts и итог Backend. При needs_review итог остаётся неизвестным; оценку 85,5 из макета нельзя переносить как fallback. Проверка/апелляция меняют только локальное состояние иллюстрации, а не серверные записи. Разделы навигации и дополнительные звонки показывают расположение информации, без обещания реализованных маршрутов.

Нужен выбор пользователя между направлениями или указание, какие части объединить. Изменения контрактов и запросы к Backend/ML для показа этих вариантов не нужны.
