# Где EVA теряет точность по сравнению с v7

Присланный архив имеет SHA-256 `35ca10e6e6c2a2f0eefe0b3d4472c64439159a9894fc967263cf6c4b823417f7`. Проверены все 383 файла по внутреннему манифесту. У товарища новые проверки применимости и хронологии, веса модели в ZIP отсутствуют. Авторские 75/79 (94,94%) относятся к единогласным решениям четырёх ИИ. По полному арбитражу на первой локальной общей точке отсчёта v7 получила 99/120. [Предыдущее парное воспроизведение](FRIEND_V7.md)

## Условия сравнения

Цель — минимум 114/120 на исходной книге и, отдельно, минимум 259/272 на других 34 чатах. Расхождения и ответы на ручную проверку остаются в знаменателе. Книга использовалась для диагностики и разработки. Остальные серии уже использовались командой в прежних экспериментах; окончательная конфигурация этой проверки фиксируется до подсчёта её результатов на них. Человеческой независимой разметки банковских звонков в этих сериях нет.

Сравниваем прежний ISSAI Qwen3.5-9B-Kazakh Q5_K_M, v7 и новый профиль на **одном и том же полном первом ответе**. Проверяются хеши входов, подлинность архива, ответ API и ссылки на реплики. Грубые флаги и остальные критерии сохраняются из основы, если профиль не предъявил отдельного основания. Все входы, ответы и доказательства остаются в игнорируемом `ml/data/`. Эталон читается отдельной командой для подсчёта. Реализация правил товарища загружается только из предоставленной локальной копии с проверенной контрольной суммой; архив не включён в распространяемый код EVA.

Профиль использует v7 для идентификации, консультации и завершения, адресную проверку EVA для потребности и ведения диалога, затем проверяет отдельные наблюдаемые события. Например, явный запрос «вы на связи?» после оставленного без ответа вопроса не исчезает при последующем «понятно». Для изменения оценки консультации модель выбирает среди эпизодов, заранее привязанных к роли и реальному месту в разговоре. Сама уплата на личную карту не создаёт автоматического штрафа по консультации: требуется установить, что оператор предложил её **вместо** ответа по существу. Порог первой реакции в три минуты не применяется.

Единогласные и спорные строки — два среза одной книги; суммировать их с первой строкой нельзя. На 34 чатах строгий фильтр исправил семь решений относительно v7 и не добавил новых расхождений. Относительно исходной EVA получено на 11 совпадений больше. Все 272 решения вошли в знаменатель; у первичного прохода 268 автоматических решений, у обоих новых вариантов — 272. До порога 95% на этой группе не хватает ещё 28 правильных решений. Выбор более осторожного варианта сделан после анализа прежде использованных наборов; это ретроспективная оценка.

В исходной книге объединённая EVA исправила 29 из 31 расхождения. Оба оставшихся решения спорны у разметчиков: в `p1-en-013` оценка консультации 10 при метке 15; в `p1-ru-022` оценка ведения 0 при итоговой метке 10. Сам флаг грубого нарушения в последнем чате установлен верно. У v6 и v7 была одинаковая общая accuracy на книге. Выигрыш относительно нашей основы идёт прежде всего от унаследованных поправок применимости и завершения; собственный вклад v7 виден отдельно на сценариях порядка событий. В новой EVA на примере `p1-ru-030` модель получает связанный эпизод «название документа → ответ клиента → указание страницы»; прежде она выбирала эти же реплики в обратном порядке. Для консультации проверяется последний конкретный ответ перед явным подтверждением решения клиентом.

На 34 остальных чатах у строгого профиля остаются девять расхождений по завершению, по восемь по потребности и ведению, семь по консультации, по четыре по идентификации и эмпатии и одно по грубым нарушениям. Для подтверждения 95% на новых разговорах нужны независимо оценённые чаты с такими случаями. На ранее подготовленных 38 диалогах оценки по восьми критериям ещё предстоит получить. Остальные три набора не заменяют эту проверку.

Оба профиля прошли обычные `POST /v1/evaluate` и `POST /v1/verify` с локальной Qwen. Адресная проверка сохранила переданный ей исходный ответ. На одном контрольном запросе получение оценки заняло 17,34 с в объединённом режиме и 17,51 с в строгом. Это единичные замеры. Полный набор ML-тестов — 181 прошёл. ## Воспроизведение

Из `ml/` используйте работающий loopback worker на 59174 с исходными весами ISSAI и локальную копию архива в `data/compare-friend-v7/submitted.zip`. Сохранённые первичные ответы и файлы экспериментального разбора находятся в `data/interaction-phase/`. Каждая команда записывает новый файл.

```powershell
$out = 'data/v7-repeat-' + (Get-Date -Format 'yyyyMMdd-HHmmss')
$groups = 'develop','reserved','pilot','public8','public14'
foreach ($g in $groups) {
  .\.venv\Scripts\python.exe -m benchmarks.v7_fusion_trial --group $g --port 59174 --out "$out/$g.jsonl"
}
$files = $groups | ForEach-Object { "$out/$_.jsonl" }
.\.venv\Scripts\python.exe -m benchmarks.v7_fusion_trial --report $files --out "$out/metrics.json"
```

Для строгого варианта добавьте `--guarded` к запуску каждой серии и укажите новые выходные файлы. Исходные IPC-ответы архива по всем 49 чатам проверены контрактом. Где были доступны прежние построчные результаты (15 DEV и 22 внешних чата), у основы и v7 совпали все 296 из 296 значений, включая статус проверки.

Для экспериментального HTTP-запуска задайте `EVA_V7_MODE=grounded` (строгий) или `EVA_V7_MODE=evidence` (объединённый), `EVA_V7_ARCHIVE` с путём к архиву, `EVA_LLAMA_WORKER_PORT=59174`, `EVA_CONSULTATION_VARIANT=consultation-v1.1` и запустите `python -m uvicorn eva_ml.app:app --host 127.0.0.1 --port 18603`. Используется обычная точка входа EVA с маршрутами оценки и адресной проверки. Откат — `EVA_V7_MODE=off` и перезапуск процесса ML. Схемы БД и исторические оценки не меняются.
