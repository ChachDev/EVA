# Дополнительная проверка критериев Freedom

## Протокол до запуска кандидата

Исходная версия кода `3c5c73a`. Первый проход — неизменённая consultation-v1.1 на локальной ISSAI Qwen3.5-9B-Kazakh Q5_K_M. Сравнение парное по сохранённому первоначальному ответу, одинаковому транскрипту и версии чек-листа. На 15 DEV-чатах исходный результат 89/120; ошибки по критериям: диалог 7, потребность 6, идентификация 5, консультация 5, завершение 5, эмпатия 2, контакт 1, грубые нарушения 0. Целевые пять критериев дают 28 из 31 расхождения.

Для разработки используются 9 чатов (50/72 у baseline). Отложены 6 чатов с разметкой команды, по два RU/KZ/EN (39/48), и 12 других ранее размеченных пилотных чатов (78/96). Все числовые суффиксы диалогов пилота, встречающиеся в первой книге, исключены из разработки для защиты от возможных языковых вариантов. Оставшиеся места в шестёрке заполняются среди одиночных семейств по SHA-256 строки `eva-targeted-v1/<id>` в пределах языка. Точные дубликаты текста и пересечение семейств дополнительно проверяет скрипт. Шестёрка ранее участвовала в общем отчёте 89/120. Пилот имеет предварительные метки Codex и ранее использовался при разработке прежней модели. Обе серии оценивают перенос конкретной новой правки; независимая банковская приёмка требует новых оценок экспертов.

Сначала сверяем исправленные и испорченные решения на девяти чатах, затем фиксируем хеш реализации. Каждая из двух отложенных серий запускается один раз на выбранной конфигурации. Если результаты расходятся, сообщаем это и оставляем профиль экспериментальным. Целевые показатели — больше правильных решений на всех строках при сохранении покрытия и грубых флагов, меньшая или равная MAE на общих завершённых чатах. Одинаковую классификацию `N/A` и `needs_review` проверяем по статусу и значению. Показываем полные итоги, ошибки N/A, время и дополнительные вызовы, включая стоимость отказа от поправки. До снятия метрик правила не выбираются по данным отложенных серий.

До контрольных запусков зафиксирован хеш `7e401836e342e0b70dfdb162967174ad9d923e690269d4e298fc7034156e535b`. Сервисный профиль `baseline-plus-targeted` использует исходные решения consultation-v1.1 и ту же Qwen для адресной перепроверки. Значения по пяти критериям выводятся из структурированных фактов. ID выбираются из допустимых реплик конкретных ролей; Trace возвращает дословную цитату и проверяет необходимую последовательность. Закрытие чата оператором проверяется по последней системной записи. Защищённое действие, неоднозначный автор, повреждённый диапазон, недостаточное доказательство и изменение официального правила ограничивают возможность поправки. Критические проверки Sentinel имеют приоритет и используют прежний промпт. На разговор приходится максимум один модельный вызов сверх сохранённого baseline.

Книга из Telegram и локальная рабочая копия содержат те же четыре листа по 120 решений и те же 15 чатов. Все ответы совпадают. Отличаются 30 ячеек ссылок на листах 3 и 4. Из 31 ошибки по принятому арбитражному эталону в 14 случаях все четыре разметчика согласились, в 17 хотя бы один ответ отличался. Это расхождение не меняет используемый эталон.

Все пять исходных ошибок идентификации в книге — случаи с эталоном N/A. Четыре из пяти ошибок завершения — ошибочное N/A при эталоне «Нет». В структуре диалога семь ошибок распределились между соседними и несоседними ступенями. Выраженные дефекты коммуникации и содержательная неполнота консультации проверяются по разным правилам. При сверке обнаружилось, что критерий структуры диалога раньше выпадал из официальной политики: таблица фактов первого прохода не соответствовала точной формулировке Freedom. Теперь официальный статус определяется по снимку канонического чек-листа. Версия с изменённым смыслом не получит старое специальное правило.

На девяти чатах проверка закрыла один ранее неопределённый случай консультации, исправила два решения по применимости идентификации и учла системную запись о завершении чата оператором. На шестёрке единственной изменившейся оценкой была структура казахского диалога: 10 → 7 при эталоне 4. Поэтому общий балл приблизился к эталону, хотя число точных ответов осталось прежним.

На 12 пилотных чатах две верные поправки по потребности были переходами с «Да» на N/A (RU и KZ). В одном другом казахском чате такая же поправка была ошибочной и по потребности, и по идентификации. Ложные N/A выросли с 4 до 6, пропущенные N/A снизились с 6 до 4. Число автоматически решённых критериев осталось 93/96. Изменения по языкам: RU 23 → 24 из 32, KZ 25 → 24 из 32, EN 30 → 30 из 32. Грубые флаги по всем размеченным чатам сохранились; на самом пилоте положительных примеров нарушений нет.

На отложенной шестёрке медиана дополнительного этапа составила 8,04 с, p95 — 10,88 с; на 12 пилотных чатах — 8,41 и 11,87 с. Во всех 18 случаях потребовалось по одному модельному запросу; первичный ответ был взят из архива. Это время перепроверки, а не полный HTTP round trip. Обобщаемого прироста точности на отложенных данных не установлено. Профиль остаётся доступен в `shadow`; режим по умолчанию не переключался. [Агрегированные метрики и языковые разрезы](targeted-metrics.json).

Все 18 синтетических сценариев порядка идентификации и грубых нарушений сохранили правильное решение и ссылки на необходимые действия, как у прежнего `baseline-plus`. Backend принял все 45 результатов и проверил 701 ссылку критериев по исходным репликам. Повтор через реальный ML-маршрут `POST /v1/verify` воспроизвёл выбранный результат с архивным первым проходом и одним вызовом локальной Qwen. Прошли 125 тестов ML, 612 тестов Backend и проверка 20 общих схем и примеров. Пропущены 10 тестов PostgreSQL без отдельной тестовой БД и один тест Windows, требующий права на создание символической ссылки.

## Воспроизведение

Из каталога `ml` в PowerShell с работающим локальным worker и исходными данными выполните команды ниже. Укажите проверенный SHA весов своего worker. Скрипт сверяет версию модели, хеши чек-листа и транскриптов с архивом `data/baseline-plus-audit-v1`; эталон остаётся только в измерителе. Для контрольных серий обязателен точный хеш программы. Выходные JSONL создаются только в игнорируемом каталоге и открываются эксклюзивно.

```powershell
$env:EVA_MODEL_REVISION='sha256:4c0beeaa5d24765d791fc6c0fee9b4a30b5e563d18dd6830c61b9993faf8e0b6'
$revision='7e401836e342e0b70dfdb162967174ad9d923e690269d4e298fc7034156e535b'
$out='data/targeted-repeat'
foreach ($cohort in 'develop','reserved','pilot','pairs') {
  .\.venv\Scripts\python.exe -m benchmarks.targeted_trial --port 59068 --cohort $cohort --revision $revision --out "$out/$cohort.jsonl"
  if ($LASTEXITCODE) { throw "Incomplete $cohort" }
}
.\.venv\Scripts\python.exe -m benchmarks.targeted_report --run $out --out "$out/metrics.json"
```

Для локального Backend используйте `EVA_AUDIT_MODE=shadow`, для ML — `EVA_CONSULTATION_VARIANT=consultation-v1.1` и `EVA_AUDIT_PROFILE=baseline-plus-targeted`. Возврат к `baseline-plus` отключает эту редакцию проверок; `EVA_AUDIT_MODE=baseline` отключает теневой запуск целиком. Формат сохранённых оценок и схема БД прежние.
