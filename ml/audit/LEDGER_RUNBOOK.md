# Проверка оценщиков и работа разметчиков

Команды выполняются в PowerShell из папки ml. Сервис работает локально через существующий контракт Backend → ML. Для отдельного проверочного экземпляра нужен свободный порт. Основная команда запуска EVA продолжает использовать исходный оценщик. В новой точке входа режим по умолчанию — off.

~~~powershell
$env:EVA_ML_PROVIDER='issai'
$env:EVA_LEDGER_MODE='resolution'
$env:EVA_SHARE_ARCHIVE=(Resolve-Path 'data/share-comparison/share.zip').Path
.\.venv\Scripts\python.exe -m uvicorn eva_ml.ledger_service:app --host 127.0.0.1 --port 18512 --no-access-log
~~~

На изолированном Backend укажите ML_URL=http://127.0.0.1:18512 и EVA_AUDIT_MODE=baseline. В этой точке входа работают GET /health и POST /v1/evaluate. Если уже загружен нужный GGUF, задайте EVA_LLAMA_WORKER_PORT в окружении ML. Для восьми последовательных чтений установите бюджет Backend с запасом относительно измеренного p95. При обычном клиентском таймауте браузера в 30 с для длительных групп удобнее пакетный запуск с последующим просмотром истории.

Чтобы повторить опыт с обычной Qwen3.5-9B, укажите EVA_LEDGER_MODE=off и EVA_ISSAI_GGUF=D:/EVA-ML/models/Qwen3.5-9B-Q5_K_M.gguf перед стартом нового процесса. В /health должно быть имя Qwen3.5-9B-Q5_K_M. Для ISSAI используется отдельный файл Qwen3.5-9B-Kazakh.Q5_K_M.gguf.

| EVA_LEDGER_MODE | Поведение |
|---|---|
| off | Первичная ISSAI с выбранным EVA_CONSULTATION_VARIANT. |
| map, examples | После первичной оценки дополнительное чтение официальной консультации. Во втором режиме включены три синтетических учебных примера. |
| spans, spans-examples | Модель выбирает из ID фрагментов исходного разговора. Код восстанавливает цитаты и проверяет автора и хронологию. |
| criterion | По одному структурированному вызову на каждый опубликованный критерий. ML возвращает метки и ссылки. Backend рассчитывает баллы. |
| resolution | Перепроверка готового ответа проверенной командой версией resolution-v2. Задайте EVA_SHARE_ARCHIVE до локального ZIP из SHARE_TRIAL.md, SHA-256 проверяется при старте. |
| identity-order | Экспериментальная проверка первого защищённого действия C03 при явно полном источнике. Служебная передача чата из закрытого списка RU/KZ/EN не считается подтверждением личности. Неизвестное событие до действия, неподтверждённая цитата или неполный источник сохраняют первичное решение. [Сравнение и границы применения](FRIEND_V7.md). |
| expert | Шаблон spans и до трёх исправлений из локального каталога EVA_LEDGER_CATALOG. Учебный и оцениваемый разговоры должны быть в разных заявленных семействах, критерий должен совпасть по версии и смыслу. |
| product | Первичная оценка и отдельная проверка ключевого утверждения по EVA_PRODUCT_CATALOG при наличии утверждённого источника и проверенного контекста конкретного разговора. |

**Человеческая разметка.** Готовы [комплект A](../data/ledger-v1/human/annotator-A.zip) и [комплект B](../data/ledger-v1/human/annotator-B.zip). В каждом редактор, те же 12 локальных транскриптов и только свой пустой бланк на 96 строк. Передайте каждому участнику команды его комплект. После распаковки разметчик открывает editor.html, выбирает свой бланк и transcripts.jsonl, отмечает реплики, ответ и причину. Сохранение скачивает его JSONL. Чтобы продолжить, загрузите сохранённый файл. В переписках под полем оценки можно указать карту консультации. Пример структуры одного факта:

~~~json
{"goal":"открыть историю","importance":"essential","state":"closed","client_id":"m0001","reply_id":"m0002"}
~~~

Допустимы состояния closed, partial, generic, open, withdrawn и unknown. Ступени v1: 20 — на все существенные просьбы даны ответ или конкретный шаг, 15 — пропущена второстепенная деталь, 10 — открыта существенная часть, 5 — только общая подсказка, 0 — отсутствует ответ по существу или доказана ошибочность ключевой рекомендации. N/A означает, что запрос не успел прозвучать. Спор о тарифе требует источника продукта.

~~~powershell
.\.venv\Scripts\python.exe -m benchmarks.human_ballots reconcile --a data/ledger-v1/human/A-saved.jsonl --b data/ledger-v1/human/B-saved.jsonl --out data/ledger-v1/human/agreement.jsonl
~~~

Сверка требует все 96 решений каждого человека, допустимые типы и существующие ID. При расхождении можно передать файл третьего проверяющего через --third. Решения без арбитража исключаются, файл результата содержит SHA-256 входов и происхождение каждой итоговой метки. Факт того, что работу выполнили независимые люди, подтверждает команда. Формат файла это установить не может.

**Учебный каталог для режима expert.** Поля верхнего уровня — format (1), chats и examples. В chats задаются source_chat и целевые ID с family и split (development или evaluation). В examples нужны id, source_chat, rubric_hash из rules_for(checklist), fragment, value, reason, human_reviewer, approval_reference. Разрешены только источники с split=development. Целевая семья должна быть явно известна; совпадение семьи, новый смысл или версия критерия исключают пример. Фрагменты входят только в данные второго чтения. Три общих синтетических примера в эксперименте не объявлены человеческими исправлениями.

**Справочник продукта.** В JSON задаются contexts по ID разговора и список facts. Контекст включает SHA-256 нормализованного разговора через digest, подтверждённые entity/product/jurisdiction, conversation_date, date_evidence и approved_by. Каждый факт содержит id, text, те же поля области действия, from/to, period_evidence, source/locator, approved_by и review=expert_approved. Встроенного каталога действительных тарифов банка нет.

**Повтор исследований.** Для аналогичного опыта на отдельной машине скачайте только публичные синтетические источники и опубликованные результаты закреплённой ревизии. Команда получения выполняет запросы к GitHub по вашей команде, сверяет git blob и не запускает код конкурентов.

~~~powershell
.\.venv\Scripts\python.exe -m benchmarks.fetch_public_benchmark --out data/ledger-v1
# Укажите порт уже запущенного worker с нужным именем модели.
$workerPort=59174
.\.venv\Scripts\python.exe -m benchmarks.ledger_trial --cohort public --spans --port $workerPort --out data/ledger-v1/repeat-public.jsonl
.\.venv\Scripts\python.exe -m benchmarks.criterion_trial --suite gold16 --port $workerPort --out data/ledger-v1/repeat-gold16.jsonl
.\.venv\Scripts\python.exe -m benchmarks.ledger_metrics --run data/ledger-v1/repeat-public.jsonl data/ledger-v1/repeat-gold16.jsonl --out data/ledger-v1/repeat-metrics.json
~~~

Каждый прогон пишет новый файл. Для публичного сравнения десяти диалогов benchmarks.public_comparison сверяет метки из четырёх опубликованных протоколов и пересчитывает MAE на одних и тех же чатах. Оригинальные тексты, бланки, первичные ответы и снимки остаются в локальной игнорируемой папке data.
