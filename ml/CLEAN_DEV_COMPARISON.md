В новом JSON появились темы, признаки идентификации и завершения, флаги качества и предположение о разрешении вопроса. В README они описаны как результаты правил. Ни один из шести файлов не содержит решений эксперта по восьми критериям Freedom. Приложенная спецификация OpenAPI описывает возможный сервис чтения данных. Основной JSON и JSONL имеют другую структуру, чем запрос к действующему оценщику.

Хотя бы один `quality_flags` есть у 19 разговоров, `resolved_guess=true` — у 54. Запрос идентификации отмечен у семи диалогов. Во всех четырёх разговорах с `identity_verified=true` действительно нашлась реплика роли `system` с подтверждением. Для аудита важен ещё её порядок относительно раскрытия сведений, которого один булев признак не показывает.

Первая строка воспроизводит исторический результат по сохранённым ответам. Вторая получена 27 новыми запросами к локальному сервису по очищенным данным. Весь повторный прогон занял 257,83 с по сумме запросов, медиана — 8,41 с, диапазон — 6,42–18,28 с. Все 216 решений совпали с исходными по значениям и статусу оценки. Эти 27 диалогов ранее использовались в проекте. Разметка ИИ годится для диагностики ошибок. Доля совпадений с независимыми экспертами на новых диалогах ещё не измерена. Через штатный `POST /v1/evaluate` запущена локальная `Qwen3.5-9B-Kazakh.Q5_K_M`. Первичная сквозная проверка получила HTTP 200 и восемь валидных решений в каждом из трёх чатов (RU, KZ, EN) и одного русского транскрипта звонка. Время после загрузки модели — от 6,74 до 11,42 с на разговор. У трёх чатов все 24 решения совпали с историческим первым проходом. У звонка проверены контракт и ссылки, экспертной оценки для него нет. Аудиофайл для этого опыта не использовался.

В целом `ended_abruptly` есть у девяти разговоров. У пяти финальное системное сообщение сообщает о закрытии чата оператором, у четырёх — об уходе клиента или потере связи. Для оценки завершения нужны автор события, предыдущие реплики и возможность попрощаться. Среди 31 расхождения исторического первого прохода сильнее всего представлены ведение диалога (7), выявление потребности (6), консультация, идентификация и завершение (по 5). Оставшиеся три — эмпатия (2) и контакт (1).

Для грубых ошибок проверена диагностическая комбинация четырёх сигналов — мошенничество, личная платная услуга, грубость и раскрытие без идентификации. В серии из 15 она выделила оба исторически положительных случая, по 13 остальным совпала с отрицательной меткой. Все 12 меток пилота отрицательные. Для переноса на другие звонки важны примеры реальных нарушений и похожих правомерных действий. Отсутствие флага в таком корпусе не даёт оператору автоматически полного балла.

### Материал для обучения

В приватном каталоге сохранены 65 входов оценщика. У звонков сохранён исходный абсолютный timestamp, а `offset_seconds` равен `null` — положение первой реплики в аудиофайле неизвестно. Пять подписанных ссылок исключены из входов. В README метка маскирования указана для всех звонков, фактически `pii_masked_present` стоит у четырёх. У пятого есть признак непоследовательной обработки персональных данных. Работа с исходными текстами и бланками выполняется локально.

В реплике указан тип автора (`role`), индивидуального ID сотрудника и времени конца фрагмента нет. Для оценки конкретного сотрудника при передаче между операторами понадобится дополнительный источник атрибуции.

В отдельном файле привязаны к хешам новых входов 72 исторические машинные оценки девяти чатов разработки. Шесть ранее отложенных чатов и 12 пилотных исключены из этого файла. Для остальных 38 диалогов (33 чата и 5 звонков) подготовлены 304 пустых решения, два независимых бланка и транскрипты со ссылками на реплики. Это кандидаты на экспертную разметку. Они могут включать переводы или варианты ранее просмотренных сценариев. Поле семейства оставлено пустым до сверки содержания.

Нашлись семь многоязычных групп, в которых совпадают время и роль **каждой** реплики, всего 16 чатов. У семи из 38 кандидатов на разметку такой же шаблон есть среди ранее оценённых. Например, в казахском и английском чатах с суффиксом `013` совпадает вся последовательность ролей и времени и отмечено предложение личной платной услуги. Английский чат уже входил в набор разработки. Совпадение структуры помогает отбирать пары для проверки содержания. Оно не доказывает, что тексты являются переводами.

Перед обучением нужно согласовать экспертные решения и доказательства по критериям, отметить переводы и вариации одного исходного разговора, затем зафиксировать непересекающиеся семейства для разработки и проверки. Будущий результат сравнивается с исходной Qwen по каждому критерию, языку и каналу, с отдельным подсчётом ложных обвинений, пропущенных нарушений, ошибок N/A и покрытия. При нескольких примерах в группе следует указывать абсолютные числа. Для проверки звонков на казахском и английском потребуются дополнительные размеченные звонки. Веса Qwen по эвристикам этого пакета не обучались.

### Воспроизведение

Для сверки готовых результатов на стенде из `ml/` достаточно следующих команд. Они проверяют весь комплект и сравнивают полные сохранённые ответы сервиса с архивом. Обращение к модели при этом не требуется.

Полный набор тестов `ml/` после изменения прошёл: 154 теста.

```powershell
$bundle = 'data/clean-dev-de20aae9'
.\.venv\Scripts\python.exe -m benchmarks.clean_dev --bundle $bundle --raw .tmp/dev-ml-repair-2111/dev.json
.\.venv\Scripts\python.exe -m benchmarks.clean_dev_labels --bundle $bundle --requests "$bundle/eva-requests.jsonl" --read-live "$bundle/live-historical-27.jsonl"
.\.venv\Scripts\python.exe -m pytest -q tests/test_clean_dev.py tests/test_contract_integrity.py
```

Для нового прогона можно создать свой приватный набор входов, бланков и ответов Qwen. Команды сохраняют результаты в отдельном каталоге и защищают существующие файлы от перезаписи.

```powershell
$bundle = 'data/clean-dev-de20aae9'
$repeat = Join-Path $bundle ('repeat-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
.\.venv\Scripts\python.exe -m benchmarks.clean_dev --bundle $bundle --raw .tmp/dev-ml-repair-2111/dev.json --requests "$repeat/eva-requests.jsonl"
.\.venv\Scripts\python.exe -m benchmarks.clean_dev_labels --bundle $bundle --requests "$repeat/eva-requests.jsonl" --out "$repeat/labels"
.\.venv\Scripts\python.exe -m benchmarks.human_ballots prepare --source "$repeat/labels/blind-source.jsonl" --out "$repeat/labels/ballots"
.\.venv\Scripts\python.exe -m benchmarks.clean_dev_labels --bundle $bundle --requests "$repeat/eva-requests.jsonl" --live-output "$repeat/live-27.jsonl" --port 18601
```
