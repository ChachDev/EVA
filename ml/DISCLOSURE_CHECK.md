# Проверка баланса и действий оператора

На локальном стенде профиль `disclosure-review-v1` дополняет исходный проход `consultation-v1.1`. Он применяется к явно полному разговору с одним ответом целевого оператора по финансовому вопросу. Остальные разговоры идут по исходному пути. Числовые баллы по-прежнему считает Backend.

На 21 синтетической размеченной реплике RU/KZ/EN строится индекс ближайших примеров по символьным триграммам с весами IDF. Для дополнительного запроса к той же Qwen индекс подбирает по одному примеру трёх действий: сообщение владельцу, сообщение о третьем лице, отсутствие раскрытия. Модель указывает фрагмент первого ответа оператора и извлекает действие. Код восстанавливает цитату по ID, проверяет автора и порядок подтверждения в системной реплике. Дополнительные пользовательские флаги интерпретируются по сохранённому тексту своей версии правила. Если факт баланса отсутствует, а широкий флаг всё же положительный, отдельно проверяются остальные виды данных из этого правила. Веса Qwen не переобучались.

В карточке со скриншота «конф инфа» — отдельный пользовательский флаг о самом сообщении конфиденциальных данных. Он сработал и в прежней записи, но модель ошибочно написала, что проверки личности не было. Система подтвердила её в `m0002`, оператор сообщил собственный баланс клиента в `m0003`. Официальный флаг о неправомерном раскрытии по этому действию отрицательный. По ведению разговора исправлены два решения: в первой реплике оператор представился без приветствия и закончил ответ без прощания. В интерфейсе название каждого сработавшего флага открывает его правило и основания.

Для этого же разговора создана новая оценка по той же пользовательской версии v4. Backend рассчитал **70,59 из 100**. Исходная оценка 100 из 100 доступна в истории. В обеих записях общий признак обнаруженного нарушения положительный. Чек-лист учитывает флаги отдельно от числовой оценки.

| Сравнение на размеченных критериях | Разговоры | Первый проход | С дополнительной проверкой |
|---|---:|---:|---:|
| Сцена со скриншота и семь синтетических сценариев разработки | 8 | 16/25 | 25/25 |
| Диагностические формулировки, ошибки которых разбирались при разработке | 4 | 7/11 | 11/11 |
| Дополнительные заранее заданные контрольные сценарии RU/KZ/EN | 4 | 8/12 | 12/12 |

В этих числах знаменатель — только заранее перечисленные решения. Ухудшений по ним не возникло. Дополнительная проверка в последовательном прогоне 16 примеров занимала 1,59–7,58 с на разговор, медиана 1,70 с. Это время поверх первого прохода, включая проверки семантики впервые встреченного правила. Все 216 решений на 27 ранее размеченных чатах DEV сохраняются: в их старых входах нет явного подтверждения полноты обеих границ, поэтому новый профиль там не вмешивается. Качество на реальных нарушениях по экспертной разметке и на многооператорных диалогах остаётся неизмеренным. [Сверка двух экспортов DEV](CLEAN_DEV_COMPARISON.md)

Для воспроизведения из `ml/` нужен уже запущенный локальный worker с той же Qwen. Каждый выходной путь должен быть новым. Первые два запуска используют синтетические входы. Параметр `--snapshot` принимает локально сохранённый запрос оценщика для дополнительной сверки конкретной карточки. Все исходные реплики и ответы хранятся в игнорируемом `ml/data/`.

```powershell
.\.venv\Scripts\python.exe -m benchmarks.disclosure_trial --port 59174 --output data/repeat-disclosure-dev.jsonl
.\.venv\Scripts\python.exe -m benchmarks.disclosure_trial --port 59174 --transfer --output data/repeat-disclosure-control.jsonl
.\.venv\Scripts\python.exe -m pytest -q tests/test_disclosure_review.py
```

Включение на ML-сервисе задаётся переменной `EVA_CONSULTATION_VARIANT=disclosure-review-v1`. Для отката установите `EVA_CONSULTATION_VARIANT=consultation-v1.1` и перезапустите только процесс ML с теми же портами worker и сервиса. Результаты, версия чек-листа, история пересмотров и БД сохраняются. Новая оценка диалога создаётся обычной кнопкой «Оценить диалог». Для конфигураций с кэшем аудита отпечаток варианта включает реализацию проверки, инструкции и обучающие примеры.
