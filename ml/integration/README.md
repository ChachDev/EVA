# Проверка EVA с реальной ISSAI

На проверочном стенде откройте **http://127.0.0.1:5186/**. Это LiveApp на HTTP. Бэкенд слушает `127.0.0.1:18500`, ML — `127.0.0.1:18501`. Порты команды 5173/8000/8001 и её БД для этого прогона не используются. [Что прошло и что осталось](./report.md).

## Проверка вручную

1. В «Новый диалог» вставьте новый транскрипт с ролями и временем; сохраните и выберите версию чек-листа. Нажмите «Оценить диалог». В карточке должны быть указаны llama.cpp и Qwen3.5-9B-Kazakh, восемь решений и серверный итог или явная причина его отсутствия.
2. Откройте критерий и перейдите к реплике. Проверьте автора и текст. Для N/A проверьте условие неприменимости и пересчитанный вес. Для «Нужна проверка» убедитесь, что у критерия нет балла, а неизвестность не записана как N/A.
3. В учебной базе оспорьте решение, укажите реплику и причину. Через «Апелляции» сохраните решение проверяющего, откройте оценку заново и сверьте исходный и текущий итог. Ручную оценку учитывайте отдельно от автоматической.
4. В «Чек-листы» измените инструкцию и шкалу, опубликуйте новую версию и оцените тот же чат по ней. Проверьте историю: первая оценка сохраняет старую версию. Для репетиции отведите пять минут всему показу, запуск модели сделайте заранее.
5. Для сырого аудио проверьте загрузку, воспроизведение и отдельный ASR-сервис; без него транскрипция вернёт 503. Готовые транскрипты звонков принимаются и без ASR.

## Повтор с чистой базой (Windows PowerShell)

Проверьте, что 5186, 18500 и 18501 свободны. Если этот стенд уже запущен, откройте его; параллельный экземпляр на этих портах не запускайте. Команды ниже рассчитаны на отдельную новую репетицию. Нужны Node 22.18+, Python с локальным ML-окружением, модель и llama.cpp, Edge и Playwright.

Из корня репозитория создайте копию исходников, контрактов и пустую папку для данных. Скрипт каждый раз выдаёт новое имя; существующая БД не удаляется.

```powershell
$mlRoot = (Resolve-Path ml).Path
$mlPython = Join-Path $mlRoot '.venv/Scripts/python.exe'
$checkName = & $mlPython -B "$mlRoot/integration/prepare_stack.py"
$stage = Join-Path "$mlRoot/.tmp" $checkName
$stage  # скопируйте полный путь для других терминалов
```

**Терминал ML** (из корня репозитория):

```powershell
Set-Location ml
$env:EVA_ML_PROVIDER='issai'
$env:EVA_CONSULTATION_VARIANT='consultation-v1.1'
# Только для уже работающего локального llama.cpp с этим GGUF: задайте EVA_LLAMA_WORKER_PORT.
# Без него ML запускает собственный worker. Пути к весам и движку — в ../ml/.env.example.
.\.venv\Scripts\python.exe -B -m uvicorn eva_ml.app:app --host 127.0.0.1 --port 18501 --no-access-log
```

**Терминал Backend.** Задайте `$stage` равным полученному пути. Используйте отдельное окружение по lock-файлу либо готовый совместимый Python. Команды установки нужны только при первом запуске окружения.

```powershell
Set-Location "$stage/backend"
python -m venv .venv
$backendPython = (Resolve-Path .venv/Scripts/python.exe).Path
& $backendPython -m pip install -r requirements.lock
$env:DATABASE_URL='sqlite:///'+("$stage/backend/data/live-check.sqlite3" -replace '\\','/')
$env:CORS_ORIGINS='http://127.0.0.1:5186'
$env:ML_URL='http://127.0.0.1:18501'
$env:ML_TIMEOUT_SECONDS='120'
& $backendPython -B -m app.cli seed-checklist
& $backendPython -B -m app.cli doctor
& $backendPython -B -m uvicorn app.main:app --host 127.0.0.1 --port 18500 --no-access-log
```

**Терминал Frontend**, с тем же `$stage`:

```powershell
Set-Location "$stage/frontend"
npm ci --cache "$stage/npm-cache" --no-audit --no-fund
$env:VITE_API_MODE='http'
$env:VITE_API_URL='http://127.0.0.1:18500'
npm run build
npm run dev -- --port 5186 --strictPort
```

**Терминал проверки**, из корня репозитория. Автотест UI запускайте на **свежей базе только с v1**. Он создаёт учебную апелляцию и публикует v2; не направляйте его в рабочую БД. Для повторения используйте новый каталог стенда.

```powershell
$env:EVA_VERIFY_ISOLATED='1'
# Если Playwright не находится в node_modules: задайте EVA_PLAYWRIGHT_PATH до установленного модуля.
node ml/integration/verify-ui.mjs
# Используйте $backendPython из терминала Backend: CLI импорта требует его зависимостей.
& $backendPython -B ml/integration/verify_batch.py --backend-dir "$stage/backend" --version 2
```

Первый тест проходит UI без перехвата HTTP. Второй импортирует локальный синтетический файл (RU/KZ/EN, семь чатов и три транскрипта звонков), выполняет десять последовательных оценок через Backend и сверяет сохранённые снимки, версии и ID. Протоколы лежат в `ml/data/live-project-check/`. На синтетическом примере 03 с единственным спорным критерием identity дополнительно можно воспроизвести рассмотрение: `node ml/integration/verify-review.mjs <UUID-оценки-03>`. Оно оставляет исходную оценку неизменной.

Для полного релизного прогона нужна также отдельная PostgreSQL БД с суффиксом `_test` (инструкция владельца в [backend/README.md](../../backend/README.md)), и локальный ASR, если в задании будет несубтитрованное аудио. Перед защитой держите модель прогретой; UI ожидает 30 секунд. После таймаута проверьте историю оценки перед повторным запуском.
