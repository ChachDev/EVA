# Подключение Frontend к Backend

Дата: 8 ноября 2026. Задача Chach: открыть фронт, проверить реальное подключение и исправить отсутствующие связи. Изменения Frontend выполнены как часть явно порученной интеграции. Git и GitHub не изменялись.

## Что обнаружено

Новый дизайн-интерфейс `App.tsx` не вызывал сохранённый `src/api/client.ts`. Он показывал синтетические диалоги, сам рассчитывал баллы, сохранял демоапелляции и чек-листы в localStorage. Переменная `VITE_API_MODE=http` этот интерфейс не подключала. Поэтому красивые экраны не подтверждали работу серверного процесса.

Живой Backend на 8000 и PostgreSQL доступны. В основной базе 65 диалогов, одна версия чек-листа, на момент проверки оценок не было. ML на 8001 не запущен; настоящий ASR не настроен. Основная база в ходе browser-проверок не изменялась.

## Что подключено

| Действие | Реальный путь |
|---|---|
| Открыть приложение | По умолчанию `LiveApp` и HTTP; демо только по явному `VITE_API_MODE=demo` |
| Список и просмотр | GET conversations/checklists; реальные ID, язык, канал, реплики; без вымышленных имён операторов и дат |
| Добавить переписку | JSON/TXT/ручной ввод → строгий разбор → POST conversations; исходные роли/время сохраняются |
| Оценить | Выбор версии → POST evaluations; баллы и evidence только от Backend; ошибка не превращается в демооценку |
| Вернуться после reload | Полная пагинированная история, выбранная оценка в URL, snapshot и актуальный review-case |
| Изменить правила | Редактор всех полей критерия → POST checklist versions с base_version; старые снимки неизменны |
| Апелляция | Причина и выбранные реплики → POST appeals с operation_id/expected_revision |
| Решение | Допустимое значение/ступень, причина, evidence → POST decisions; текущий итог пересчитывает Backend |
| Аудио | Raw upload → ASR job; понятная ошибка отсутствующего ASR, ID сохранённого файла; состояние задания по URL, роли и переход к разговору |
| Длинный запрос модели | Известный ограниченный ML 422 → безопасный Backend 422 с `ml_context_limit_exceeded`; неизвестный ответ остаётся 502 |

Вызовы API сосредоточены в клиенте. JSON ограничен 1 МиБ, аудио 25 МиБ. Идемпотентные действия повторяют прежний UUID при том же содержимом формы; автоматического повтора inference нет. После ответа на апелляцию читается актуальная ревизия: старый receipt не подменяет текущий результат.

N/A отделён от неопределённости. Грубая ошибка берётся из серверного флага. Ссылки используют строковые ID реплик, шкалы — допустимые значения конкретного чек-листа. Запись без snapshot доступна для чтения, пересмотр заблокирован. Поздние ответы оценки/проверки ролей не переключают пользователя на прежний разговор/задание.

## Проверки и пределы доказательств

- В браузере против основного Backend: отображаются все 65 диалогов, ошибок страницы и API-загрузки нет. Чтение не заменялось фикстурами.
- TypeScript и production-сборка Vite прошли.
- 100 тестов Frontend: HTTP-клиент, ошибки, лимиты, полная история, канонические тела, UUID, разбор JSON/TXT и недопустимые роли/время.
- 185 тестов Backend: ML transport, API reliability, OpenAPI и diagnostics. Падений нет; осталось прежнее предупреждение deprecation TestClient/httpx. Полная PostgreSQL-серия в этой задаче не запускалась.
- Отдельный browser workflow с настоящим Backend и изолированной SQLite: создание переписки, синтетическая оценка, переход к evidence, апелляция, решение с изменением 100 → 90, сохранность 90 после reload, публикация v2 по Enter, сохранность snapshot v1, 422/503 без ложной оценки, загрузка WAV с пустым браузерным MIME и честный отказ ASR.
- Проверен мобильный экран без переполнения страницы. Снимки только синтетического стенда сохранены в игнорируемом `frontend/artifacts/integration/`.

Синтетический evaluator явно обозначен `fixture / browser-test-only`; это не тест качества или скорости настоящей модели. Во время проверок обнаружены и исправлены ошибки разбора TXT с квадратными скобками и сохранения шкалы по Enter. Итоговый прогон успешен.

## Что ещё требуется

1. ML-владелец запускает настоящий сервис оценки и реализует локальный ASR. Затем команда проверяет живую цепочку, задержки и языки. Полный путь реального распознавания в этом аудите не подтверждён.
2. Backend реализует прямые ручные решения и обязательное утверждение каждой оценки. Сейчас UI честно показывает предварительный результат; решение апелляции не является утверждением.
3. Для новой обработки context-limit нужен контролируемый перезапуск существующего Backend на 8000. Чужой работающий процесс не останавливался; текущие исходники и изолированный сервер проверены.
4. Для большой истории нужен агрегирующий список проверок: сейчас читаются все страницы и review-case каждого результата, максимум четыре параллельных чтения.
5. Список аудиозаданий, исправление текста ASR, долговечная очередь оценки, аутентификация и права остаются отдельными серверными задачами. Нынешний job можно открыть по ID/сохранённому URL.
