# EVA · аудит операторов Freedom

Эксперимент использует ту же локальную ISSAI Qwen3.5-9B-Kazakh Q5_K_M, что и действующий ML-сервис. Настройка по умолчанию — baseline. Основание для выбора режима и ограничения измерений приведены в [исходном протоколе](../ml/audit/BASELINE.md) и [результатах](../ml/audit/RESULTS.md).

## Правила Freedom

Проверены Student Guide (4 страницы) и Chat Quality Checklist (3 страницы). Data 2 (5 слайдов) описывает компанию. DEV включает 60 синтетических чатов и 5 реальных звонков с готовой расшифровкой. Источник доказательства — неизменённый текст разговора. Аудио нужно, если проверяется акустический признак. В этом эксперименте такие признаки не оцениваются.

| Критерий | Разрешённые значения · вес | Когда применяют N/A |
|---|---|---|
| Контакт | Да/Нет · 10 | Не разрешено. В первом ответе нужны приветствие на языке клиента и представление. |
| Потребность | Да/Нет/N/A · 15 | Для ответа с самого начала достаточно информации. |
| Идентификация | Да/Нет/N/A · 20 | Запрос не требует идентификации. Для защищённого действия проверка должна быть подтверждена заранее. |
| Консультация | 0/5/10/15/20 или N/A · 20 | Клиент не успел сформулировать запрос. Ступени идут от ошибочного/отсутствующего ответа до полного решения или конкретного следующего шага. |
| Эмпатия | Да/Нет · 15 | Не разрешено. Учитывают вежливость и реакцию на конкретное неудобство. |
| Управление диалогом | 0/4/7/10 · 15 | Не разрешено. Оценивают понятность, последовательность и предупреждение об ожидании. |
| Завершение | Да/Нет/N/A · 5 | Чат оборвался до возможности завершения. |
| Грубые ошибки | Да/Нет · 0 | Не разрешено. Оскорбление, предложение личной платной услуги в обход компании, раскрытие конфиденциальных сведений. |

Backend рассчитывает 100 × Σ(вес × доля выполнения) / Σ(применимых весов). Для шкалы доля равна ступени / максимуму. Округление финальной суммы до сотых — half-up. Например, 7/10 при весе 15 даёт вклад 10,5 до нормировки. Флаг не изменяет сумму. N/A исключает вес только при выполнении условия. При неопределённом решении или пустом знаменателе итог отсутствует. Правила реализованы существующим серверным агрегатором; модель не выполняет арифметику. Порог первой реакции, теги и вложения не оцениваются.

## Путь запроса

1. Ручной импорт или адаптер Freedom даёт сообщения с устойчивыми ID. Структурное событие `event: identity_verified` допускается только у системной реплики. В нормализованном JSON поле `id` служит `utterance_id`. Дополнительный перевод хранится в `translation` отдельно от оригинала и не отправляется оценщику. На входе ручного импорта разрешены неизвестная роль, явное отсутствие времени (`timestamp: null`), `speaker_id`, `language: mixed`, `quality`, подтверждённые `offset_seconds` / `end_seconds`. Поле `source` принимает `target_operator_id`, `complete_start`, `complete_end`, `gaps`. Если ISO-время есть, но начало аудио не подтверждено, смещение остаётся null. Язык разговора задаёт значение по умолчанию для реплик без индивидуальной языковой разметки. Автоматическая диаризация/определение языка в этом пути не выполняются.
2. **EVA Trace** строит упорядоченный индекс исходных сообщений, проверяет автора, цитату, диапазон символов и доступные границы аудиозаписи. Символьные смещения считаются в Unicode code points; конец исключён. По частному решению может быть несколько связанных реплик. Для пропуска сохраняется проверенный участок и доступные сведения о его полноте. Проверяемая точная цитата может быть целой репликой. Её наличие отделено от оценки смысла.
3. **EVA Policy** использует снимок переданного чек-листа и версионируемое приложение правил Freedom (`ml/eva_ml/audit_policy.json`). Специальное правило применяется лишь при совпадении ID, инструкции, типа, шкалы и условий N/A с официальным критерием. Новые формулировки оцениваются по переданному правилу. Для пользовательских зависимостей допустим список `depends_on` с ID критериев; при публикации проверяются существование и отсутствие циклов.
4. **EVA Score** оценивает обычные критерии; **EVA Sentinel** — отдельные нарушения и сводный официальный флаг. Профиль `rubric-v1` просит в одном структурированном ответе решения с точными цитатами. Профиль `events-v2` сохраняет действующую оценку обычных критериев по наблюдаемым фактам; отдельное чтение ищет только события идентификации и запрещённые действия. Профиль `source-events` дополнительно сверяет подтверждённое событие и первое однозначное декларативное сообщение о балансе на RU/KZ/EN в исходном порядке. Вопросы, цитаты и гипотезы не соответствуют грамматике таких утверждений. В иных случаях используется семантическое извлечение и рубрика Score; неподтверждённая положительная идентификация передаётся на пересмотр. Дополнительное чтение выбирает существующие ID ограниченного круга говорящих, а порядок проверки и защищённого действия сопоставляется обычным кодом. Утверждения клиента не являются системной проверкой. Подтверждённое нарушение имеет приоритет в сводном флаге, неопределённость других правил остаётся видна. При невозможности обработать весь источник показывается ручная проверка; незаметного отсечения хвоста нет. Если полный критический запрос превышает окно, Sentinel проверяет до шести фрагментов (до 5 000 символов, с перекрытием при наличии места), передаёт ID ранее подтверждённых системных событий и сохраняет все проверенные и пропущенные диапазоны. Слишком длинная единичная реплика помечается непрочитанной. По таким частям можно найти основания для пересмотра; итог «нарушений нет» или обвинение по частичному источнику не выставляются. Обычные критерии, для которых полного контекста недостаточно, остаются на ручной проверке.
5. **EVA Review** использует существующие append-only апелляции с operation_id и expected_revision. В экспорт входят первоначальная оценка, текущие решения, время, автор, причина, ссылки, версия, снимок источника и экспериментальные данные. Для реального действия используйте ссылки на сообщения, для аудио — только подтверждённые смещения. Объяснение модели помечается как модельное. Отдельный JSON предназначен для будущего преобразования в схему Dynamics. Подключение к CRM отсутствует.

## Включение и отключение

Используйте существующие локальные команды из README каждой роли. Перед запуском **Backend** задайте в его PowerShell:

```powershell
$env:EVA_AUDIT_MODE='shadow'   # baseline | shadow | experiment
$env:EVA_AUDIT_REVIEW='true'
$env:ML_TIMEOUT_SECONDS='90'  # только для экспериментального стенда
```

Перед запуском **ML**:

```powershell
$env:EVA_CONSULTATION_VARIANT='consultation-v1.1'
$env:EVA_AUDIT_PROFILE='baseline-plus' # доступны также source-events, events-v2, rubric-v1
$env:EVA_AUDIT_COMPONENTS='trace,policy,score,sentinel'
```

Для UI экспериментального стенда задайте `VITE_API_TIMEOUT_MS=100000`. В штатной конфигурации тайм-ауты прежние. Перезапускайте только свой экземпляр. Для отключения всех ML-компонентов на Windows задайте `EVA_AUDIT_COMPONENTS=off` (приложение также принимает пустую строку). Обычный baseline не обращается к `/v1/audit`. Отключение `trace` не отключает обязательную проверку ссылок и авторства. Отключение `policy` убирает дополнительные инструкции. Выключенные `score` и `sentinel` делегируют свои критерии прежнему оценщику. `EVA_AUDIT_REVIEW=false` отключает экспериментальный экспорт и пересчёт версий; сохранённые штатные апелляции по-прежнему доступны.

- **baseline** вызывает прежний `POST /v1/evaluate`. Для ранее не поддерживавшихся источников с неразличимыми операторами или потерянной частью запись получает ручную проверку.
- **shadow** сохраняет штатный результат, затем в фоне сравнивает эксперимент на том же снимке. Профиль `baseline-plus` получает сохранённый ответ и проверяет отдельные критерии. Порядок однозначных системных событий проверяется локально. Если нужно дополнительное чтение, все его вопросы объединяются в один запрос к той же Qwen. В «EVA Review · история и экспорт» откройте «Перепроверка исходной оценки», чтобы увидеть исходный ответ, проверенный вариант и основание. Сбой кандидата сохраняется отдельно. При остановке процесса до завершения фоновой задачи сравнение может остаться pending; первичная оценка сохраняется. [Эксперимент и команды воспроизведения](../ml/audit/BASELINE_PLUS.md).
- **experiment** вызывает `POST /v1/audit`. Ответ содержит прежний `evaluation-response` и дополнение `audit`; схема и пример находятся в contracts. Backend заново проверяет хеш входа и чек-листа, модель, цитату, роль, порядок и смещения до сохранения. В UI откройте «EVA Review · история и экспорт». Кэш в памяти ограничен 16 успешными расчётами; ключ включает вход, профиль, конфигурацию, правила, модель и промпт. Незавершённый результат не переиспользуется. Для уже работающего внешнего worker кэш разрешён только при заданной проверенной `EVA_MODEL_REVISION`.
- **Повторный расчёт версии**: `POST /api/v1/evaluations/{id}/versions/{version}` с телом `{}`. Для новых весов расчёт выполняется без LLM. Для новых/изменённых критериев и их зависимостей выполняется отдельная оценка; остальные решения берутся из исходных автоматических результатов. В приложении к результату хранится также пересчёт с ранее принятыми поправками человека. Повтор для того же источника, ревизии пересмотра и версии возвращает сохранённую запись. Старые записи остаются доступны.
- **Экспорт**: `GET /api/v1/evaluations/{id}/audit` (`eva.review.v1`). Экспорт может содержать клиентский текст и предназначен для разрешённого локального использования. Производственный ASR и внешние LLM не подключались.

## Откат

Для оперативного отката верните `EVA_AUDIT_MODE=baseline` и перезапустите Backend. Для отключения дополнительного интерфейса задайте `EVA_AUDIT_REVIEW=false`. Кэш исчезает при перезапуске ML. Для повторного запуска измерений выбирайте новые имена результатов: программа специально не перезаписывает существующие файлы. Новая таблица `eva_audit_runs` создаётся только при включении эксперимента. Исходная оценка, снимок и дополнение эксперимента записываются в одной транзакции. Схемы существующих таблиц и Alembic head не изменены. Откат не требует удаления таблицы, очистки хранилища, downgrade или правки ранее сохранённых решений.

На ветке с тематическими коммитами код можно отменить через `git revert` собственных коммитов, от последнего к первому; список показывает `git log --oneline a8ee9d3..HEAD`. Проверка `ml/integration/audit_rollback.py` делает SQLite backup в отдельную папку и читает ту же историю исходным кодом a8ee9d3. Для рабочей PostgreSQL используйте резервную копию средствами вашей эксплуатации; откат этого стенда проверялся на SQLite. Старое приложение не редактирует дополнительные поля новых разговоров.
