# Наборы, слепая разметка и конкурсный файл Freedom

**Операторский сценарий.** Импортируйте официальный набор штатной командой Backend (`python -m app.cli import-dataset --file data/<файл>.json --group DEV`) и сохраните официальный чек-лист (`python -m app.cli seed-checklist`). В рабочем HTTP-интерфейсе откройте **Наборы**, выберите импортированную группу и версию правил, нажмите **Оценить весь набор**. Сервер фиксирует список всех ID независимо от фильтров таблицы. Запуск не ждёт окончания инференса. Состояния: «В очереди», «Оценивается», «Сохранено», «Ошибка». После перезапуска страницы выберите сохранённый запуск. «Повторить ошибки» повторяет только failed, не создавая новых записей для успешных разговоров.

**Хранение и отказоустойчивость.** PostgreSQL — основной адаптер, SQLite — поддерживаемое локальное окружение. Дополнительные таблицы `eva_batches`, `eva_batch_items`, `eva_blind_labels` не изменяют исторические оценки, ревизии Alembic или существующие таблицы. Запуск идемпотентен по составу группы, режиму, версии чек-листа и `EVA_BATCH_REVISION`. При изменении промпта, модели или профиля присвойте новую ревизию конфигурации Backend; старая очередь продолжится только под прежними режимом и ревизией. Worker использует ту же модель и семафор, что и одиночная оценка. На каждый диалог сохраняется стабильный ID оценки. PostgreSQL выдаёт задание под блокировкой строки с SKIP LOCKED; сохранение результата, исходного снимка и завершение задания — одна транзакция, защищённая токеном аренды. Если процесс погиб до commit, задание снова доступно по истечении аренды (таймаут ML + 45 секунд). Повтор вычисления после такой аварии возможен, повтор сохранённого результата — нет. Для shadow завершение задания означает сохранение первичного результата; отдельная фоновая проверка может оставаться pending при аварии после commit. Она не попадает в конкурсный файл.

Чтобы остановить фоновые вычисления, задайте `EVA_BATCH_WORKER=false` и перезапустите Backend. История, документы, выгрузка и разметка остаются доступны. Для модели оставлен прежний режим `EVA_AUDIT_MODE=baseline`; включение `shadow` не меняет действующий ответ. До отката кода остановите worker и сохраните обычную резервную копию БД; убирать дополнительные таблицы не нужно. Возврат к коду предыдущей версии через обратные локальные коммиты сохраняет записи очереди и разметки для последующего включения. Старый код видит обычные оценки. Для сравнения с CRM продолжает использоваться отдельный экспорт EVA Review; CRM не подключалась.

**Экспорт.** Источник формата — «Приложение к студенческому гайду. Как сдать результаты», JSON 1.0, с. 1–3. Кнопка «Скачать results.json» доступна для завершённого DEV или PROD. Экспорт берёт **первоначальный автоматический результат данного запуска**, не решение разметчика, апелляцию или теневой кандидат. Имя модели берётся из сохранённого ответа. Для статуса ok проверяются ровно восемь критериев, шкалы и допустимые N/A, доказательства, исходный порядок автора и текста, сводный балл и отдельный флаг. Внешние ID: contact, discovery, identification, consultation, empathy, dialogue, closure, critical. Номера реплик считаются с единицы, включая ботов и события. Числовой результат считает Backend; N/A перераспределяет вес, critical сам его не обнуляет. При недостаточных данных сохраняются ID и `status:error`, пустой массив criteria, null score и пояснение. Ошибка не подменяется N/A. При незавершённом задании, неподтверждённой модели, demo/stub или неполном манифесте выгрузка блокируется. Если все задания завершились до получения хотя бы одного реального ответа, честное имя фактически использованной модели неизвестно и выгрузка блокируется.

DEV должен содержать 60 чатов и 5 звонков. PROD — 10 контрольных чатов. Расположение для сдачи: `results/dev/results.json` и `results/prod/results.json`. Файлы интерфейс скачивает локально. Отправка организаторам и публичная публикация — отдельное действие.

Откат реально проверен на копии SQLite: `ml/.venv/Scripts/python.exe ml/integration/batch_rollback.py ml/data/audit-components/final-integration/verified-receipt.json backend/data/audit-integration/final-integration/audit.sqlite`. Backend из коммита `2bb527e` открыл исходную и пересчитанную оценки и историю апелляции. После возврата новый Backend увидел сохранённую очередь и слепую анкету.

Если задание падает: на пути оценки EVA код 502 означает, что Backend не принял ответ ML по схеме или смысловым проверкам. Код 503 возвращается при таймауте или недоступности ML, заполненной очереди одиночных запросов либо ошибке БД. По одному HTTP-коду нельзя установить виновника конкретного старого запроса; сопоставьте время, маршрут и журналы Backend/ML. Например, отказ соединения с портом модели — другая причина, чем существующая реплика с искажённой цитатой.

Для локальной проверки выгрузки из запечатанного архива реальных оценок и **той же** snapshot-базы есть команда из `backend/`:

```powershell
..\ml\.venv\Scripts\python.exe -m app.export_archive --archive ../ml/data/dev-ml-repair-2111/sealed/DEV65-2026-11-07.zip --database ../ml/.tmp/dev-ml-repair-2111/backend/data/batch65-final.sqlite --group DEV --out data/contest-rehearsal-repeat/results/dev/results.json
```

Проверено на архивном DEV: 65/65 записей, 54 ok, 11 error из-за незавершённых критериев, ни одного вымышленного ID. Каждая оценка сверена с сохранённым record и снимком, без новых модельных вызовов. Это проверка формата, не прогон нового профиля на 65 разговорах. Контрольного PROD в эксперименте не было.

**Слепая разметка и качество.** В разделе наборов нажмите «Разметить вслепую». На экране только разговор, версии правил и шкалы. Нужно выбрать восемь ответов, включая при необходимости «Недостаточно данных», и имя разметчика; N/A разрешается только правилами. Сравнение появляется после сохранения, повтор той же анкеты безопасен, изменить поданную анкету этим же именем нельзя. Это локальная учётная метка, не аутентификация. Режим скрывает подсказку на экране, но не может доказать, что человек никогда раньше не открывал модельную карточку. Отдельно существующий механизм апелляций отвечает за пересмотр действующих оценок. Экран качества показывает покрытие диалогов, совпадения по языку/критерию, N/A и грубые ошибки. Ответы разных разметчиков считаются отдельно; это не автоматически установленная арбитражная истина. В карточке оценённого критерия короткая подсказка привязана к официальной формулировке и источнику снижения. Тарифы или банковские операции из внешних источников она не предлагает.

**Проверки.** Из `backend/`: `..\ml\.venv\Scripts\python.exe -m pytest tests/test_batches.py tests/test_openapi.py`. Для PostgreSQL укажите отдельную базу с суффиксом `_test` в `EVA_TEST_DATABASE_URL` и запустите `python -m pytest tests/test_postgres.py`. Проверены выдача разных заданий конкурентным воркерам PostgreSQL 16.8, восстановление незавершённой аренды, защита от записи устаревшим воркером, переживание рестарта, отказ/повтор, экспорт и исключение заглушек. Для браузерной проверки из корня укажите `EVA_PLAYWRIGHT_PATH` до установленного Playwright и запустите `ml/.venv/Scripts/python.exe ml/integration/batch_ui.py`. Сценарий поднимает отдельные loopback-сервисы и использует synthetic-demo. [Измерение дополнительной проверки на локальной Qwen](../ml/audit/QUESTIONS.md).

**Открытые образцы и границы заимствования.** Все механизмы выше реализованы в EVA самостоятельно, файлы, рубрики и данные сторонних команд не включены. Из [d00mathon](https://github.com/useing123/d00mathon/blob/39f9cc1f2c39ec97d864fa99c7505392c2d29b28/cqa/evaluator.py#L306) полезна идея перепроверки нестабильной шкалы; медиану нескольких ответов не переносили. Из CQA Evidence изучены [критерии восстановления пакета](https://github.com/CurtisEllese/cqa-evidence/blob/c56de3fe265f389a252b146ee9c481c8ce6cf409/docs/audit/durable-batch-acceptance.md) и [контроль цитат](https://github.com/CurtisEllese/cqa-evidence/blob/c56de3fe265f389a252b146ee9c481c8ce6cf409/backend/evaluator.py#L48). [D1maX737](https://github.com/D1maX737/cqa-freedom/blob/d21cb0287d401b6b9f177a9b974e0d0e19dd3460/server/accuracy.js#L66) — идея сравнения с независимым ответом. [AuditLens](https://github.com/btwamibatman/AuditLens/blob/2fe60be14a345437e0ab478b3a1fb0bec2c0c0a1/backend/app/features/evaluations/export.py#L311) и [CQA Ground Truth](https://github.com/karimbeksultan/CQA-Ground-Truth-) — ориентиры проверки покрытия и происхождения ответа; схему задало приложение Freedom. [FreeDoom](https://github.com/realadikaah/FreeDoom-CQA/blob/5fbffe0097c3a560fb0507eeb7d42ba885fe4385/server/insights.py) — идея конкретной рекомендации после оценки, без заимствования их модели или продуктовых показателей. Для отдельного испытания использован тестовый дистрибутив [Zonky PostgreSQL](https://github.com/zonkyio/embedded-postgres-binaries); бинарники, сторонние данные и приватные результаты в Git не включены.
